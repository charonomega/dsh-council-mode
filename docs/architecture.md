# 议会模式 / Council Mode

当前版本：**0.2.4**，适配 DeepSeek Harness 0.2.1-rc.2 与 CLI Worker 0.8.2-local.1。

成员在同一个持久房间中直接广播、定向交流和引用回复。后台只负责验证身份、保存消息、调度成员；不运行主控模型来转述、选择发言人或总结。主控用于邀请/登记成员、接纳用户议题，以及用户明确要求的总结或任务分配。

## 使用

1. `/council on` 或输入框左侧「议会」开启模式，在「议会」标签页加入至少两位成员。
2. DeepSeek 使用 DSH 原生可续聊子智能体，其他模型沿用对应 CLI Worker。已有成员可以继续使用，不需要重建。
3. 在议会页的「自主议会消息」输入框写议题并点「开始讨论」。这条路径直接入队，不调用主控模型。Enter 发送，Shift+Enter 换行。
4. 成员自行决定发言、向谁发言、回应哪条消息或让出发言；新消息自动送到目标成员。成员忙碌时按序排队，不打断当前执行。
5. 可以发送补充、暂停派发、继续讨论、结束议题或开始新议题。暂停/结束阻止新派发；已运行的成员完成当前轮，其后续发言不会继续转发。
6. 分配文件修改等执行任务前先结束讨论并等待成员完成。普通会话输入框继续用于邀请成员、选型卡片、明确要求主控总结或分配任务。

普通会话输入议题也可由主控调用 `council_convene` 入队，然后结束主控回合；后续成员交流不再需要它。

## 消息和执行协议

邀请阶段只允许固定的“已就绪”请求，不允许提前起草立场。主控通过 `council_convene` 先发布完整议题与讨论要求，结束准备回合且全体成员就绪后，后台才统一开场。

- `council_inbox()`：成员直接从持久收件箱读取本轮新增原文，返回真实作者、收件人与回复标识；首轮附带角色和名册。后续不重发历史。

- `council_post(to, content, reply_to)`：`to="all"` 广播，或使用成员 id / 无歧义名称定向发送。作者从真实执行身份解析，不接收客户端指定的作者。
- `council_read(after_seq, limit)`：只读本人发出或收到的房间记录；定向回复不能扩大原消息的接收范围。
- `council_yield(reason)`：本轮不再发言，回执不显示为聊天气泡，也不触发其他成员。
- CLI 工具可以带 `mcp__dsh_worker_tools__` 前缀。新议题必须通过真实工具读取和发言；最终正文、JSON 与伪调用不会自动变成群消息。0.2.0 历史房间保留其原有结构化出口兼容。
- 每个成员同一时刻只运行一轮，每轮最多一条实质发言。每次唤醒只是一条收件箱通知，不含讨论正文；规则由随包技能 `skills/dsh-council-member/SKILL.md` 按需加载。宿主钩子执行开场、身份、工具范围和先读后发检查。
- Native 成员通过公开 `agents.resume` 恢复原来的 sessionId，保留模型、预设、权限和角色，并在讨论期间持有同一个 Agent 实例；后续仅 followup 一条新消息通知，不创建新子会话。
- CLI 成员复用原 Worker 会话；发送以唯一投递 id 和实际 runId 绑定，完成只能由同一 runId 确认。议会自己的后台 job 通过 SDK waiter 接收结果，不唤醒主控；其他 job 仍按原流程通知。
- 讨论轮只开放议会消息工具和技能读取，CLI 的 DSH 工具桥同样收窄；原有 CLI 内建工具及文件权限仍由 CLI 自身控制。议会角色不是文件权限沙箱。

## 默认预算与恢复

每个议题最多 **24 条消息（含用户输入）、每位成员 6 次唤醒、10 分钟**，每次发言不超过 1200 字符。触及预算停止新派发，保留尚未投递的记录；这些限制可在插件配置中调整。队列为空时进入空闲，不轮询模型。

“结束议题”旁的 **不限次数** 开关可取消当前议题的消息条数和成员唤醒次数限制；讨论时限、单条长度和单轮一次发言仍保留。默认关闭，新议题重新使用默认限制；当前议题的开关状态随日志保存。关闭后按已有计数恢复限制，超额时暂停；已经暂停的议题开启后仍需点击“继续讨论”。

消息与投递状态存入父会话的 `plugin:council/room` 日志，投影版本 3；旧日志与 0.1.12 的无损 JSON 修复保留。界面显示当前议题与最近 10 个已结束议题，完整记录留在会话日志。

重启或热更新后房间暂停，不自动重新发送或消耗模型。若重启前仍有执行中的投递，会显示“未确认”，核对成员日志后在界面选择“已收到”或“重新投递”，再继续。断线/超时同样不会盲目重发。

命令：

- `/council start <议题>`：新议题；`say <补充>`：补充当前议题。
- `/council pause|resume|stop`：暂停、继续、结束；`room-status`：状态。
- `/council unlimited on|off`：切换当前议题的次数限制。
- `/council room-resolve <投递id> received|retry`：核对当前自主议会投递。
- `/council on|off|status`、`invite <cli> <role>`：模式与成员管理。
- 旧版 `/council resolve <seq> <成员id> received|retry` 只用于历史 relay 台账，不会把旧讨论自动迁移为新发言。

## 数据与边界

讨论内容发送给收件成员所用的模型服务商，与各成员的正常使用一致。定向消息限制的是议会消息路由；父会话所有者仍可查看全部议会记录，这不是跨账号的私密聊天服务。

成员名单在议题开始时固定；后来加入或修改角色的成员从下一议题生效。分叉会话不能复用原父会话的成员绑定，需要重新登记。计划模式、只读主沙箱、子会话会拒绝派发。工具/API 来自当前 DSH 与 CLI Worker 版本，上游大版本升级须重新验收。

此次真实验收覆盖两个 DeepSeek 原生成员与一个 Codex 成员：发布要求前均只回复“已就绪”，正式开场后完成 7 条房间消息、12 次成员执行及自动空闲。原生成员各 5 轮保持最初的 sessionId；Codex 保持同一个原生会话，收件箱读取的作者、消息编号和正文与房间记录一致。讨论期间主控没有新增回合。其他 CLI 由同一接口接入，未声称已做真实联调。

插件不再把完整历史或固定规则拼进每轮 prompt。模型服务仍会使用成员自己的会话历史，Codex 的累计输入 token 也包含缓存命中、系统规则与工具说明；这与当前上下文窗口大小、每轮新增议会消息量是不同指标。

## 开发与安装

源码、测试和构建脚本在本目录。修改客户端后先用 DSH Node 24 执行 `scripts/build-client.mjs`，再执行 `--check client.js`、`--check index.js` 与 `--test tests/*.test.mjs`（当前 113 项）。

使用原生插件管理器从**项目外的 tgz** 安装，当前包名 `local-dsh-council-mode-0.2.4.tgz`。不要对指向开发目录的本地 bundle 执行 remove；插件管理器可能清理链接目标。升级前备份现有包，等待运行中的任务结束，安装后刷新客户端；不要直接写 DSH 配置或 CLI Worker 包。

## 历史修复记录

下面是对应版本当时的机制和恢复命令，不覆盖上文 0.2.4 自主议会协议。

## 0.1.12 重启后会话恢复修复

- 议会成员和任务的可选字段只在有值时发往客户端，避免显式 `undefined` 被 DSH 的无损 JSON 校验拒绝。修复重启后 `api-session/added ... is not lossless JSON data`、CLI Worker 设置读取失败和会话从侧边栏消失的问题。
- 保留旧版成员、原生身份、权限信息和未完成任务的原有语义；投影状态版本仍为 2，不改写会话日志。
- 新增 5 项协议边界回归。`scripts/probe-session-wire.mjs` 只读重放本机议会会话，使用宿主的真实 JSON 校验器检查输出；支持拼接的 Zstd 帧，只输出会话计数、字段路径与哈希。

## 0.1.11 CLI 流式显示修复

- CLI Worker 同一条时间线记录会保持 id 并持续更新正文。缓存合并现在保留顺序、用最新快照替换整行，完成后无需切换视图才能补齐；晚到的历史页不能覆盖较新的实时内容。
- 成员正文与状态按快照 revision 取较新来源；版本相同时优先采用携带正文的成员快照，避免另一条名册订阅滞后时残留「正在生成」。
- 「正在生成」只对应 Worker 当前 runId，下一轮开始不会把上一轮已经完成的气泡重新标成生成中。
- 新增 7 项回归，包含已脱敏的真实 CLI Worker 0.8.2 快照，持续挂载同一前端 hook 完成两轮回放。`scripts/replay-worker-timeline.mjs` 可只读回放指定本机 Worker，输出长度与哈希，不保存讨论原文。

## 0.1.10 可靠性修复

- CLI 任务按投递回执绑定 runId，兼容 CLI Worker 0.8.2 折叠后的时间线 id；失败运行的部分输出不再算完成。
- 逐项结果为 accepted / completed / failed / cancelled / uncertain；原生 sendMessage 只证明 accepted，当前宿主没有按消息关联的可靠完成回执，因此不自动升为 completed。CLI 与原生成员同时派发。
- 原生成员必须是当前父会话持久目录中的 continuable 子会话；旧的未核验登记保留展示，但重新登记核验前不打开原生聊天。未知模型不会伪填为 DeepSeek。
- 角色意图与实际权限分离。只读任务必须使用 CLI plan/read_only 或可核验的原生只读沙箱；角色本身不提供权限。写入范围按规范化真实路径检测父子目录、分隔符、Windows 大小写与链接路径重叠。范围是任务约定与冲突检测，不是路径沙箱。
- 前端缓存累计历史与实时窗口；切换父会话或删除成员会清理缓存。分页暂缓/失败不会冒称历史已全部加载。
- 所有任务阶段受超时约束，包括名册、投递、读取和清理。取消等待不会按 Worker id 盲停另一个运行；已投递任务可能继续，请在成员面板核对后停止。

### 送达不确定时恢复

发送前先写 sending，收到回执再写 delivered。断线、超时或进程退出造成的 sending/uncertain 不会自动重发，也不会让后续消息越过它。核对成员会话后，由用户执行：

- `/council resolve 12 <成员id> received`：确认已经收到第 12 条。
- `/council resolve 12 <成员id> retry`：明确允许重试第 12 条；随后省略 message 调用 council_convene。

旧版进程内游标无法追溯迁移。升级后的新投递才进入持久日志；不要把旧讨论全文当作新消息补发。
