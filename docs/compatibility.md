# CLI Worker 兼容性维护

议会 0.3.1 面向 DSH 0.2.2-rc.1。CLI Worker 0.8.2 与 0.8.7 的快照、投递和时间线契约由回归用例覆盖，当前分发运行时为 0.8.7-council.1。

## 选择安装包

| 安装方式 | 内容 | 升级方式 |
| --- | --- | --- |
| 完整整合包 | 议会、固定版本 CLI Worker、对应宿主 UI 组件和协议注册 | 统一升级整合包 |
| 仅议会包 | 议会功能与客户端 | 分别维护议会与已安装的 CLI Worker |

完整包携带的四个 UI 组件与宿主版本绑定。根清单声明 `engines.dsh`，宿主在导入 bundle patch 前判断版本兼容性。维护者需要核验新宿主后再扩展范围。仅议会包采用同样的已验证版本范围，使用独立 CLI Worker 的既有 UI 与协议。

## 适配边界

`lib/adapter.js` 集中检查 `watch`、`followup`、`submitMessage`、`runtime.get` 与 `harnessConversation.lookup`。缺失能力时，议会在派发前给出明确错误。私有工具桥的读取集中在这个文件，便于上游接口变更时维护。

- 快照校验兼容 JSON 字符串与对象，并验证议会消费的身份、状态和容器字段。
- `selectedBusy` 覆盖准备、排队和清理阶段。看到完成文字后，调度仍等待忙碌状态解除。
- `uncertain` 保留为未确认投递，继续讨论前需要人工核对。未知终态采取同样处理。
- 投递保留同一请求标识和精确 `runId`，结果只归属于对应执行轮次。
- CLI Worker 暂时不可用时，暂停、停止、状态查看和投递核对仍可执行。
- 开场全员检查与实际派发前核对主会话、原生成员的归档状态。命中归档时显示原因并停止新派发，已接收任务继续收尾。
- 客户端历史缓存由 Session 与 API 生命周期共同管理，旧异步请求无法写入新连接的缓存。
- 支持 0.8.7 的 `response.id` 分段，同时保留旧行结构与流式空白。

## 更新 CLI Worker 时

1. 从固定上游发布包开始，核对包完整性与版本。
2. 比较接口、快照与生成的 Typert 定义，以及新版本的 UI 挂载配置。
3. 重新评估本地补丁。0.8.7 使用上游增量输出和终态分类，同时保留首行指令与 Windows PATH 两项修复。
4. 更新 vendor、补丁、文件清单及对应回归，执行 `npm test`、`npm run build`、`npm run check` 与 `npm run pack:release`。
5. 在全新 profile 分别验收完整包和独立 CLI Worker 加仅议会包，检查真实 RPC、客户端启动、设置与冷恢复。
6. 在专用议会测试会话核对消息、成员身份、执行轮次和用户可见结果后发布。

## 升级中的任务和历史

先等待活动任务完成，再通过插件管理器更换包。升级或重启后的旧议题会暂停，原消息与成员保存在 Session 日志中。对于未确认投递，核对成员记录后使用现有的 received/retry 操作，再继续讨论。

后续上游版本仍需按这些契约验证。版本号范围与当前明确的运行能力检查共同决定可用性。
